# T1.2: Periodos contables (apertura y cierre)

## Objetivo
Controlar en qué fechas se puede registrar contabilidad: periodos mensuales agrupados por ejercicio (año calendario, como exige la legislación salvadoreña), con cierre secuencial y reapertura controlada. Implementa la regla 6 de CLAUDE.md: **no se puede registrar en un periodo cerrado**.

## Modelo `contabilidad.PeriodoContable`
| Campo | Descripción |
|---|---|
| `anio`, `mes` | Ejercicio (2000–2100) y mes (1–12). Únicos en conjunto. |
| `fecha_inicio`, `fecha_fin` | Primer y último día del mes (calculados). |
| `estado` | `ABIERTO` / `CERRADO`. |
| `cerrado_por`, `cerrado_en` | Último cierre. |
| `creado_por/en`, `modificado_por/en` | Usuario y marca de tiempo (regla 5). |

Restricciones en **base de datos**: `(anio, mes)` único, `mes` entre 1 y 12, estado válido, `fecha_fin >= fecha_inicio`, un periodo cerrado tiene `cerrado_por` y `cerrado_en`.

## Reglas (en `contabilidad/services.py`)
1. **Crear ejercicio**: genera los 12 periodos del año, todos abiertos. No se puede crear un ejercicio que ya existe.
2. **Cierre secuencial**: un periodo solo se cierra si **todos los anteriores** (incluidos los de ejercicios previos) están cerrados. No se cierra un periodo ya cerrado.
3. **Reapertura controlada**: solo el **superusuario**, con **motivo obligatorio**, y solo el **último periodo cerrado** (no puede haber periodos posteriores cerrados).
4. **`validar_fecha_registrable(fecha)`**: lanza error si la fecha no pertenece a ningún periodo o si su periodo está cerrado. Es el punto que usará T1.3 al contabilizar asientos (y T1.3 agregará al cierre la verificación de asientos pendientes).
5. Crear ejercicio, cerrar y reabrir quedan en la bitácora (acciones nuevas `CERRAR` y `REABRIR`; la reapertura guarda el motivo).

No se eliminan periodos.

## Permisos
- Consultar: cualquier usuario autenticado.
- Crear ejercicio y cerrar: **Contador** (y superusuario).
- Reabrir: **solo superusuario**.

## API
| Método | Ruta | Descripción |
|---|---|---|
| GET | `/api/periodos/?anio=2026` | Periodos (sin paginar), filtro opcional por año |
| GET | `/api/periodos/ejercicios/` | Años existentes con cantidad de periodos abiertos y cerrados |
| POST | `/api/periodos/ejercicios/` | `{anio}` crea el ejercicio |
| POST | `/api/periodos/{id}/cerrar/` | Cierra el periodo |
| POST | `/api/periodos/{id}/reabrir/` | `{motivo}` reabre el periodo |

## Frontend
Página **Periodos contables** (menú, todos los roles): selector de ejercicio y tabla de los 12 meses con estado, fechas y quién cerró. Contador: "Crear ejercicio" y "Cerrar" (con confirmación). Superusuario: "Reabrir" (pide motivo).

## Pruebas (`manage.py test contabilidad`)
Creación del ejercicio (12 periodos, fechas, bisiesto), ejercicio duplicado, año fuera de rango, cierre secuencial dentro del año y entre años, cierre doble, reapertura (solo superusuario, motivo obligatorio, solo el último cerrado), `validar_fecha_registrable`, restricciones de BD, permisos por rol en la API y bitácora.
