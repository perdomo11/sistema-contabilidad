# T4.1: Presupuesto institucional anual definido por la gerencia

## Objetivo
Iniciar el Bloque 4 con el primer paso del modelo **top-down** de `CLAUDE.md`: la gerencia fija el **monto institucional** de cada ejercicio, que después (T4.2) se distribuye a los departamentos (centros de costo) y, dentro de ellos, por cuenta y mes. El documento base sitúa el presupuesto en los costos "predeterminados o estimados, base de la proyección y del control presupuestario" (sección 2.3) y en la "identificación oportuna de desviaciones presupuestarias" de la contabilidad por áreas de responsabilidad (sección 2.4); el control de la ejecución es T4.3.

En esta tarea solo se registra y controla el monto institucional: no hay distribución ni ejecución.

## Modelo (app nueva `presupuesto`)
**`PresupuestoInstitucional`**: uno por ejercicio.

| Campo | Descripción |
|---|---|
| `anio` | Ejercicio (2000–2100), único. No exige que el ejercicio contable ya exista: el presupuesto se prepara antes. |
| `monto` | Monto institucional de egresos (gastos) del ejercicio, `NUMBER(18,2)`, mayor que cero. Es el valor de la versión vigente. |
| `version` | Número de la versión vigente. |
| `estado` | `BORRADOR` → `APROBADO` → `CERRADO`. |
| `descripcion` | Texto libre (lineamientos de la gerencia). |
| `referencia_aprobacion`, `aprobado_por`, `aprobado_en` | Documento que respalda la aprobación (p. ej. acta de junta directiva), quién y cuándo la registró. |
| `creado_por/en`, `modificado_por/en` | Trazabilidad. |

**`VersionPresupuesto`**: historial **inmutable** de cada cambio del monto.

| Campo | Descripción |
|---|---|
| `numero` | Correlativo por presupuesto (1, 2, …). |
| `tipo` | `INICIAL` (alta), `AJUSTE` (cambio en borrador), `APROBACION`, `MODIFICACION` (cambio de un presupuesto aprobado). |
| `monto`, `monto_anterior` | Monto resultante y monto previo. |
| `motivo`, `referencia` | Justificación y documento de respaldo. |
| `registrado_por`, `registrado_en` | Quién y cuándo. |

## Reglas
1. Un presupuesto por ejercicio; monto > 0 y con 2 decimales (`Decimal`, nunca `float`).
2. **Todo cambio del monto crea una versión** y queda en la bitácora (valor anterior y nuevo). El presupuesto siempre refleja la última versión.
3. **Borrador**: el monto se ajusta libremente (versión `AJUSTE`; el motivo es opcional).
4. **Aprobar** (borrador → aprobado): exige la referencia del documento de aprobación; crea la versión `APROBACION`.
5. **Modificación presupuestaria** de un presupuesto aprobado: exige **motivo y referencia**; crea la versión `MODIFICACION`. (T4.2 agregará que el nuevo monto no puede quedar por debajo de lo ya distribuido.)
6. **Cerrar** (aprobado → cerrado): ya no admite cambios.
7. Los presupuestos **no se eliminan** (historia y auditoría); un error en borrador se corrige con un ajuste.
8. La descripción se puede editar mientras no esté cerrado (bitácora, sin versión).

### En la base de datos (Oracle)
- Restricciones: `monto > 0`, estado válido, año en rango, `anio` único, `(presupuesto, numero)` único; si está aprobado o cerrado, la referencia y el aprobador son obligatorios.
- Trigger `TRG_VERSION_PPTO_INMUTABLE`: las versiones no se modifican ni eliminan.
- Trigger `TRG_PRESUPUESTO_REGLAS`: un presupuesto no se elimina; uno cerrado no se modifica; al actualizar, `MONTO` y `VERSION` deben coincidir con una versión registrada (ningún cambio de monto sin versión).

## Roles
- **Contador**: registra el presupuesto que aprueba la gerencia (alta, ajustes, aprobación, modificaciones y cierre).
- Cualquier usuario autenticado puede consultarlo (los jefes de área lo necesitarán en T4.2/T4.3).

## API
| Método | Ruta | Uso |
|---|---|---|
| GET | `/api/presupuestos/` | Lista por año (desc.) |
| POST | `/api/presupuestos/` | Alta: `anio`, `monto`, `descripcion` |
| GET | `/api/presupuestos/{id}/` | Detalle con `versiones` |
| PATCH | `/api/presupuestos/{id}/` | Descripción |
| POST | `/api/presupuestos/{id}/cambiar-monto/` | `monto`, `motivo`, `referencia` |
| POST | `/api/presupuestos/{id}/aprobar/` | `referencia` |
| POST | `/api/presupuestos/{id}/cerrar/` | — |

Bitácora: entidad `presupuesto`, acciones `CREAR`, `MODIFICAR`, `APROBAR` (nueva) y `CERRAR`.

## Frontend
Nueva sección de menú **Presupuesto → Presupuesto institucional**:
- Tabla de ejercicios con monto vigente, versión y estado (insignia).
- Alta del presupuesto de un año (Contador).
- Detalle del ejercicio: monto vigente, datos de aprobación, acciones según estado (ajustar o modificar monto, aprobar, cerrar, editar descripción) e **historial de versiones** con la variación de cada cambio.
